## 2026-06-23 update — closed by ADR-0012 (in-repo thin UI)

The plan in this document — reuse hermes-web-ui's Vue client, delete its
`Runs` / `RoleBindingModal` / `SessionMetrics*` views, rewrite its store from
polling to SSE, collapse 12 statuses to 4 in `AgentRoomTaskPanel.vue` — has
been **superseded** by [ADR-0012](adr/0012-in-repo-thin-ui.md).

### Why the pivot

The deletion + rewrite work was itself the bulk of the cost. Once we had
ADR-0011's mapping table and the §6.1.1-§6.1.3 backend shells in hand, a
~300-500-line Jinja2 + single `app.js` client renders the same contract
without npm, without a build step, and without a second repository. That is
strictly cheaper than reusing hermes-web-ui and removes the "must clone an
external SPA" hole in the ADR-0007 independence story.

### What is preserved from this audit

- The 12-state vocabulary on the UI side and the 4-state vocabulary on the
  server side. The new in-repo UI implements the same derivation table that
  hermes-web-ui would have implemented.
- The `/api/agent-room/*` compatibility surface (sessions thin shell). It
  stays a public contract any consumer can target — including a real Vue
  SPA if someone wants to build one — but we don't ship one.
- The four D1-D4 calls (sessions = tag, 4-state, SSE only, RoleBindings
  read-only via `/healthz`).

### What changes

- §6.1.4-§6.1.7 in PLAN.md are marked superseded; §6.1.4'-§6.1.6' replace
  them and target `agent_room/server/ui/`.
- `hermes-web-ui` is no longer a v1.0 dependency in any artifact.
- The `examples/vue_ui_smoke.md` planned in §6.1.7 is replaced by
  `examples/ui_smoke.md` walking through `/ui` directly.
